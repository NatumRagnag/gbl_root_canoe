# gbl_uefi boot artwork

The supplied PNGs are retained under `targets/magisk_module/assets/splash-source`.
They are assets supplied by the user; this tool does not regenerate the artwork.

Build the seven independent assets:

```sh
python tools/splash/build_splash.py targets/magisk_module/assets/splash-source targets/magisk_module/module/efisp/splash tools/splash/build/layout-preview
```

Requires Pillow. Source dimensions are 890x1920. The on-device canvas is fixed at
1200x2608, with a 1104x2381 centered image. Alpha is composited over black before
lossless compression. The builder's PNGs are layout previews; exact firmware
render output is generated by the shared-scaler host test below.

`SFBSPL03` format: 32-byte little-endian header (`8s6I`): magic, source width,
source height, compressed payload size, uncompressed byte count, raw pixel CRC32,
reserved zero. Payload is LZMA-alone (lc=3, lp=0, pb=2) with a known 64-bit decoded
length in the LZMA header. Decoded pixels are row-major BGRX at source resolution.

The reader caps file size at 3 MiB, fixes output dimensions and length, restricts
LZMA properties before entering the decoder, and checks CRC32 before drawing.
Its maximum working allocation for one image is about 20 MiB, then only the
12.5 MB display buffer is retained for redraw during the current BDS session.
There are no boot-time writes or persistent random counters.

Artwork is attempted only after the three-second volume-key check and after a
persisted default entry has been resolved. Holding volume up, first boot without
a saved default, and an unresolved default all enter the ordinary menu without
initializing the artwork GOP/RNG/decoder path. Manual launches from that menu do
not initialize artwork either. Existing storage and console code still runs;
this is an escape path around optional artwork, not an independent hardware
recovery channel.

The loader links `RawLzmaDecompressLib`, containing only the existing decoder
sources. It deliberately has no constructor, guided-section registration or
fixed physical-address handler table. The earlier e87582d7 build must not be
used. Moving drawing alone would not repair that build's constructor defect.

Test the exact EDK2 LZMA SDK and C scaling implementation on all images:

```sh
make -C tools/splash test
python3 tools/splash/test_boot_flow.py --check-build
```

This also tests malformed/truncated inputs with UndefinedBehaviorSanitizer.
Outputs `tools/splash/build/1.bgrx` ... `7.bgrx`, each 1200x2608 BGRX. Hardware GOP
and boot-time redraw behavior still need device testing; host tests cannot prove
the display timing of a subsequent Android loader.
The flow test compiles the actual default-selection/dispatch source with mocked
firmware services. The build audit checks the generated constructor list and
link map as well as the final image. Neither replaces a real UEFI boot test.
